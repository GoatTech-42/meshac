# chunkveil decoy-write crash (ilhsmc 2026-10-10 09:29) - analysis and fix

Status: patch UNCOMPILED and UNTESTED. Built against 9fea277 by reading source only. VERIFY items below need the rig.

## What the code did
ChunkDataMixin swaps buried ores for stone/fake ore inside the LIVE LevelChunkSection while a chunk packet is sized and encoded, then writes the cached "real" state back.

## Root-cause candidates (in order of confidence)
1. Cache key had no dimension. Key was (chunk x, chunk z, section). Overworld (0,0) and nether (0,0) shared entries, so a swap list built for one dimension was applied to the other: fakes written at positions that were not ores, and the cached "real" state restored over whatever was there. That is decoys written into real terrain and a section whose palette/size no longer matches. Also explains why it showed up on a join (many chunks sent at once, both dimensions loaded).
2. Size and write phases each did their own cache lookup. Any invalidation between them (reveal() on a block update, a stale entry) gave a different swap list, so calculateChunkSize and extractChunkData disagreed and the fixed-size buffer overflowed.
3. Restore used the cached "real" state, not what was in the section at swap time. A stale entry (block changed without sendBlockUpdated) permanently overwrote the real block.
4. No thread guard. If any mod or async chunk-sending path builds the packet off the server thread, the unlocked swap races the main thread.

## Fix in this patch
- Cache key = (ServerLevel, chunk, section); size capped; invalidate takes the level.
- calculateChunkSize records the exact Mod[] per section; extractChunkData reuses them. No plan for a chunk = send it unveiled (fail open).
- swap() validates current == cached real, skips stale entries (and drops the cache), returns the states it actually saw; restore() puts back exactly those and checks.
- Any restore mismatch trips Veil.fail(): anti-xray off for the run, one error log line.
- Veiling only happens on the server thread.
- /mesh veil [xray|esp|off] runtime kill switch for staff.

## Not in this patch
- Copy-the-section encoding (no mutation of live sections at all) is the cleaner end state; needs LevelChunkSection copy API check on 1.21.11 / 26.1 / 26.2 / 26.3.
- Fake-ore only near real ore (spec gap), offline /mesh ban (needs profile-cache lookup API per version).
