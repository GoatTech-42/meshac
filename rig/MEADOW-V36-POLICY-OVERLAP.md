## Overlap surface (v36 tip vs meshac bundle tip 0107)
Rig-only drivers (src/rig, not in release builds):
- **NoFallSpoof / NoFallSpoofGate - ALIGNS (good catch-side driver).** While airborne past fallDistance>3 (default), sends ServerboundMovePlayerPacket.StatusOnly(onGround=true) every k-th airborne tick (default k=2), honest air packets between, client fall distance untouched. meshac's statusOnly() path scores these in the same 5-claim ground window, air packets leave the window alone, so the 3rd fake claim flags "nofall ground spoof" (default k=2: ~6 airborne ticks). Matches the GS-A/GS-C catch rows in WINDOW-POWDER-PIN-DRAFT (0104). Requires grace expired and no exemption - normal rig conditions.
- **MicroHop / MicroHopGate - FINDING F1: catch-side mismatch.** The module sets a real vertical velocity (clamped 0.10-0.25, default 0.2) every 15-20 ticks while moving on a clean pad. A real impulse makes vanilla send honest onGround=false packets on the way up. meshac's microhop check (Movement.java:298) only counts GROUND-CLAIMED packets (s.ground and the claim window), so this driver cannot trip the flag by construction - it exercises the zero-FP/legit half, not the catch half. Arithmetic if the claims were spoofed: dy band 0.10-0.25 sits inside meshac's (0.005, 0.30); cadence 15-20 ticks vs hopClock decay (1 per 30 packets) accumulates ~+1.4/hop, so two spoofed hops would flag. Consequence: nb-microhop-cheat from 0103 is STILL blocked, differently - the meadow module now exists but drives the wrong half of the check. A catch-side driver needs forged ground claims on rising packets (a spoof variant), or the rig must drive packets directly.

Release modules:
- **Fly + FlyAntiKick (0068/0069/0072) + FlyPending (0071) - no conflict.** Antikick default OFF; when on, one vy=-0.04 write every kick-delay ticks (default 20, clamped 5-80), skipped while already descending. This targets vanilla's floating kick, not meshac: one -0.04 tick per 20 does not reset meshac's flyBuf (Movement.java:263 accumulation continues across the hover spans), and meadow's own case file names meshac's gravity-expectation fly check as the catch. FlyPending's conditional-cancel ownership (player+world bound, exact-vy compare) is clean and has no server-visible effect.
- **Speed - known cat-mouse surface, unchanged policy.** budget/budgetIce settings are an explicit self-clamp mirroring meshac's SustainBudget (meadow comment cites "meshac candidate4" - untrusted provenance, unverified which meshac build; current meshac caps are SustainBudget.packetCap/perTick on a 0.13 base). v36's round-2 rework measures real position deltas (what the server sees) - matches what meshac actually measures, which is the honest way to model the check. No new overlap beyond the documented E1/candidate4 history.
- **Strafe - outside current meshac coverage (known gap).** human mode: no speed gain, 10 deg/tick turn cap. meshac has no pinned rotation-rate check (ROTATION-SNAP-AT-PLACE-PROPOSAL is proposal-stage only). Consistent with meshac's own gap docs.
- **ElytraFly - known surface.** human mode keeps a minimum descent per tick (ElytraBudget.minDescentPerTick) so the glide keeps losing energy; meadow's comment says this is to stay under meshac's Glide sustain - consistent with GlideWindow.capWindow semantics (log-only glide window on meshac's side).
- **Scaffold - FINDING F2: unverified meshac claim.** ScaffoldGate's walking cap (3.0-3.6 blocks/s) cites "meshac's 4.0 blocks/s bridging line". I find NO placement-rate check in the meshac surface reviewed to date (Movement paths + Interact hook). Either stale meadow-side lore or a check outside this review's coverage - flagged for the reviewer to resolve, not silently accepted. meshac's real scaffold-relevant lever today is the rotation-snap-at-place PROPOSAL (unpinned). Legit-mode pacing (log-normal gaps ~170-240ms, tower ~280-360ms) and snap-to-mouse-step aim are below every meshac speed envelope by construction (static reads).
- **HoleESP / basefinding finders / hud / crosshair / hitcolor / trail - no overlap.** Render-only, world-scan and drawing; no packet sends per the patch docs (0047's "this path sends no packets" wording pass).
- **FreeLook - camera-only.** 0001 steers Speed/Strafe by freelook yaw; affects movement direction, not packet shape.
